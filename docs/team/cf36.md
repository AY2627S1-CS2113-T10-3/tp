# Chang Feng - Project Portfolio Page

### Project: BusyNotFree

## Overview

BusyNotFree is a Java command-line application that helps freelancers manage clients, projects, dated tasks and events. It supports saving work between sessions. My contributions focus on deleting records safely and recovering deleted projects while preserving their relationships and identifiers.

## Summary of Contributions

- **Code contributed:** [tP Code Dashboard](https://nus-cs2113-ay2627-s1.github.io/tp-dashboard/?search=cf36&breakdown=true).

- **Enhancements implemented:**
  - **Deletion with confirmation:** Implemented `project.delete`, `client.delete`, `client.delete_note`, `task.delete` and `event.delete`. Prompts identify the selected record before requiring `yes` or `no`; invalid answers preserve the pending operation, and end of input cancels it. Client deletion rejects clients with projects, preventing broken ownership links. Notes are numbered to support selecting the correct note. Evidence: [project deletion](https://github.com/CF36/tp/commit/5fdd99b85eeedfc6b50bac9b5691d6da96f5cb75), [confirmation](https://github.com/CF36/tp/commit/214d9b3).
  - **Trashcan and project recovery:** Implemented `trashcan.list` and `trashcan.restore PROJECT_ID`. Deleted projects retain their tasks and events; deleted clients retain their notes. Restoration preserves original IDs, dates, project status and task completion. It checks client availability and ID conflicts before changing data, and removes the trash entry only after successful registration. Extended storage to retain trash entries across restarts and load older files without a trash section. This required coordinating deletion, model relationships and persistence. Evidence: [trashcan implementation](https://github.com/CF36/tp/commit/d6b9607b0fe1728bfaad6c61cf73c500d1e48f84).
  - **Permanent trashcan cleanup:** Added `trashcan.empty` to remove all retained projects and clients, including their activities and notes, after `yes` confirmation. Reused the existing confirmation lifecycle so cancellation, invalid answers and end of input preserve entries. Active records and ID counters remain unchanged; emptying is persisted through the existing save path. See the [implementation](../../src/main/java/busynotfree/model/TrashcanManager.java) and [command coordination](../../src/main/java/busynotfree/command/CommandHandler.java).
  - **Design and validation:** Separated snapshot ownership into `TrashcanManager` and listing/restoration handling into `TrashcanCommandHandler`; retained confirmation coordination in `CommandHandler`. Added tests for missing and invalid IDs/indexes, confirmation, cancellation, preservation of unrelated records, repeated deletion/restoration, snapshot isolation, save/load and prevention of ID reuse. Extended coverage for trashcan emptying, including extra arguments, repeated emptying, blocked save commands, cancellation at end of input and clearing previously saved entries without resetting ID counters.
